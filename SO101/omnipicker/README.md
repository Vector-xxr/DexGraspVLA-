# OmniPicker 夹爪（485 + Modbus RTU）

智元 OmniPicker（SDK 里叫 OP1，2025 款），单自由度自适应夹爪。这里是它在 SO101 遥操 / 采集里的驱动。
**没有触觉，力是电机电流换算的**；寄存器值 0~255 和牛顿的对应关系手册没给、也没标定过。

所有命令都在 **SO101 目录**下跑：

```bash
cd ~/yuhang_workspace/算法/DexGraspVLA-/SO101
PY=~/miniforge3/envs/dexgraspvla/bin/python
PYTHONPATH= $PY -m omnipicker.selftest                    # 不连硬件的自检
PYTHONPATH= $PY -m omnipicker.jog                         # 只读：固件、状态、延迟，不动
PYTHONPATH= $PY -m omnipicker.jog --opening 0.5           # 走到一半开度（会动）
PYTHONPATH= $PY -m omnipicker.jog --grip --force 32       # 合拢夹住，3 秒后自动松开（会动）
PYTHONPATH= $PY -m atom_robot.ar5.collect --end-effector omnipicker --preview   # 遥操采集
```

`PYTHONPATH=` 是为了清掉 ROS 塞进来的路径，不清会在 import 时炸。

## 接线

6 针接口（1.25 mm 带锁扣）：

| 夹爪脚 | 接到 |
|---|---|
| 1、2 | 24 V |
| 3（L） | hkvtech 转换器 **A** |
| 4（H） | hkvtech 转换器 **B** |
| 5、6 | GND（转换器的 GND 也接过来） |

* **这块 hkvtech `HKV_USB-RS485/CANFD` 转换器的 A/B 和智元文档是反的。** 照文档（4 脚接 A）是零回包，
  反过来就通了（2026-10-19 实测）。它那盏绿灯是电源灯，发数据时不闪，别拿它判断有没有发出去。
* 串口用 by-id：`/dev/serial/by-id/usb-hkvtech.cn_HKV_USB-RS485_CANFD_20260717-if00`。
  它是 CDC 串口（ttyACMn），主臂 SO-101 也是，**别写 /dev/ttyACM0**。
* 夹爪后盖里的拨码：485 是 **1、2 号 ON、其余 OFF**（出厂是 3、4 号 ON = CAN）。这台是带拨码的 30 版板。
* 120 Ω 终端电阻（背面 R47）出厂焊着，485 要保留。
* 夹爪没有触觉模块（带触觉的是 OmniPicker 3）。

## 自适应模式是什么

每条指令带「目标位置、速度、力、加速度、减速度」。夹爪朝目标走，电机出力不超过「力」：

* 一路没碰到东西 → 走到目标停下，状态「已到达」；
* 中途碰到物体 → **停在物体上，按设定的力一直夹着**，状态「堵转」（就是「夹住了」）；
* 夹着的东西被抽走 → 继续往目标走，手册说会报「物体掉落」（**没实测过**）。

所以「抓」就是发「合到 0」，**夹多紧由夹持力决定**。不会越夹越紧：
2026-10-19 夹人手，夹持力 32，停在位置 32（约 15 mm）、0.5 秒后报堵转，夹 3 秒力矩读数一直 21~24，和空夹一样。
**夹着时改夹持力 0.26 秒内生效**（10-20 实测：32 → 64，力矩读数 24 → 48，位置不变）。

反过来，**目标正好在物体表面就算「到达」，力会卸掉**（10-20 实测：到达后力矩读数半秒内 42 → 1）。
所以模型部署时不能把输出的开合原样发过来 —— 训练标签是夹住时的实测开合，正好就在物体表面。
往合拢方向要多给一点余量（目标 = 输出 − 约 0.1），见 `算法/DexGraspVLA-/README.md` 的「部署：夹爪那一维要换算」。

## 采集时怎么用（`collect --end-effector omnipicker`）

**按数据集采，主臂扳机不起作用，夹爪只听键盘：空格夹紧、O 松开**（2026-10-20 定的，状态机在 `keyflow.py`）。
存到 `~/atom_episodes/new/任务名/`，每个任务一个目录，另有 `dataset.json` 记任务名、prompt、力和速度：

    待机 ─P─▶ 任务名称是: ─回车─▶ 语言prompt是: ─回车─▶ 测试力度和速度
         ─回车─▶「开始采集数据集，按回车开始采集：」─回车─▶ 录制 ⇄ 暂停（回车）
    同名（new/ 下有这个目录，一条没存也算）─▶ 问是否续采 ─y─▶ prompt、力、速度沿用，夹爪张开，直接到待录
    不管新采续采，开数据集时夹爪都先自动张开一次（上电它会自己合拢找零位）
    录制 / 暂停 ─S 存盘 / R 丢掉，臂回 0 位─▶ 待录 ─回车─▶ 下一条 …     待录 ─P─▶ 下一个数据集

    测试：进来时夹爪自动张开一次；↑↓ 夹持力、←→ 速度、空格 夹紧、O 松开 —— 只有这一步能调，整个数据集用这一组
    待录：空格 夹紧、O 松开、N 删最后一条存盘的（y 确认，可以连着往前删）、
          T 回测试重新调力和速度（只在一条都没存时；续采沿用记下的值、跳过测试，用它补调）
    暂停：**空格、O 不起作用**（动了夹爪数据里会看出中断）        q 退出
    录制：空格 夹紧、O 松开 —— 臂先冻住、只动夹爪；夹紧等夹爪报「堵转」（= 夹住）或空夹合到底，
          松开等张开到位（都最多 4 s），臂才自动接着跟，照常录帧

空格只管夹、O 只管松（不是交替）：已经夹着再按空格只提示，不会变成松开。等「堵转」而不是等位置不变，
是因为 10-20 实测夹爪碰到套筒位置就不变了、力约 0.5 s 后才建起来，原来的判法提前放臂、套筒被带歪。

每一步能按的键都会在那一步打出来。暂停时臂冻住、不录帧（按下后臂滑到停稳那一小段照录，不然接着录时
会一帧跳过去）；再按回车从主臂当前位置接着跟。
速度档位 32、48 … 240、255（每档 16），夹紧和松开共用，改了从下一次夹紧 / 松开起生效；
下限 32 是因为再慢会被「卡死」检测误判。夹持力和速度的范围都在 `config.py` 里，要放宽改那里。
完整的键位表在 SO101 的 `数据采集.md` 第 2.5 节。

## 实测规矩（驱动已经守着，直接用协议的人自己要守）

全部来自 2026-10-19 / 20 的台架测试和三次事故复现：

1. **张开目标不超过 210**（约 99 mm）。冲过 255 会**回绕**（位置读数 238 → 1），而且**固件内部也跟着乱**：
   再发「去 240」它反而往张开端顶、一动不动。**只能断电重启**（上电会自己合拢找零位，指间别放东西）。
   原来上限是 240，只验证了「从空位张开不冲」；10-20 采集时**从夹紧状态松开**，速度 176 冲过 255 回绕了一次。
   对比测试（力 64 合到 0 顶 1 秒再松开）：目标 200 / 210 在速度 128、176、255 下都不冲；
   目标 230 速度 128 就冲到 241。冲过头只在「从夹紧松开 + 目标靠近张开端」时出现，跟速度、按键快慢无关。
   加大减速度（255）反而会冲 3~10，别用。
2. **张开方向的力不低于 64。** 力 32 张开时出力不够，速度、力矩读数乱跳，最后冲过 255 回绕（复现两次）。
   合拢方向用 32 没问题。所以驱动里**夹持力只用在合拢方向**，张开用 max(64, 夹持力)。
3. **状态比位置晚约 0.2 秒**更新，刚发完指令读到的是旧状态；判断到没到位看位置。
   到位后状态常常还显示「移动中」一段时间，不是卡住。
4. **合拢方向会冲过目标 5~10 个单位再退回来**，张开不会。夹东西时碰到就停了，影响不大。
5. 运动中力矩读数瞬间会冲到 250 左右（设定管不住动态峰值）；慢速（64）时只有 30~70。
   夹易碎的东西降速度。
6. 目标 0 = 合到两指碰上然后一直顶着：力 64 停在 1~3，力 32 停在 7（挤不动指尖软垫）。

驱动里另外两道保护：位置一个周期跳变超过 100 判回绕；「移动中」、离目标还远、位置却 1.5 秒不动判卡死
（航凯夹爪 9-30 卡死的教训）。两种都**停发、报错、退出采集**，不自动恢复。错误码非 0 同样处理。

## 性能

| 项目 | 实测 |
|---|---|
| 读状态（20~24） | ~7.5 ms：发出到回包第一个字节 7.6 ms，回包 15 字节一次到齐（转换器攒整包）。115200 下线上只占 ~2 ms，其余是夹爪处理 + 转换器 |
| 写指令（10~15） | ~8 ms（刚开串口后的第一次 57 ms） |
| I/O 线程 | 100 Hz（10-21 从 50 改），单测实际 99.5 次/秒；录一帧时读数平均旧 9 ms、最多 14 ms（50 Hz 时 14 / 24 ms） |
| 全行程张开 | 速度 64：2.2 s；128：1.4 s；255：0.9 s |
| 重复定位 | 开到 128 三次都是 128；合到 16 是 15~16 |

## 出问题时

| 现象 | 先查 |
|---|---|
| 完全没回包 | A/B（这块转换器要反接）、24 V、拨码在 485、上位机四个参数 |
| 报「位置回绕」 | 断电重启夹爪；以后别把 open_max 调过 210、open_force 调低于 64 |
| 报「卡死」 | 看指间有没有卡东西、机构转不转得动；断电重启 |
| 报「过温 / 超速」等错误码 | 断电重启；过温就先停一会儿 |

## 文件

| 文件 | 干什么 |
|---|---|
| `protocol.py` | Modbus RTU 收发、CRC、帧格式；不做安全判断 |
| `gripper.py` | 驱动：I/O 线程、自适应开合、夹持力、各道保护；接口同 atom_robot 的 `HandDriver` |
| `config.py` | 参数（端口、地址、力、速度、上限），**要持久改就改这里** |
| `jog.py` | 单独调夹爪，默认只读；`--grip --change-force` 测夹着时改力 |
| `keyflow.py` | 采集的按键流程（纯状态机，不碰硬件） |
| `selftest.py` | 不连硬件的自检（假夹爪模拟堵转、回绕、卡死、丢包；按键流程） |

atom_robot 那边只接了一层：`end_effector.py` 的 `--end-effector omnipicker` 和 `--omnipicker-*` 参数，
`collect.py` 按 `keyflow.py` 执行动作、显示状态。
