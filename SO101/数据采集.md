**主臂 SO-101 带着从臂 AR5 走**，主臂手柄上的扳机控末端（OmniPicker / 航凯夹爪或因时手的开合）。
这不是 Vision Pro 那条路，那条见 [数据采集_servoJ](../../../数据_硬件/灵巧手遥操/VR设备/数据采集_servoJ.md)。

所有命令都在 **SO101 目录**下跑（`python -m atom_robot.ar5.<模块>` 要从这里找包），环境是 `dexgraspvla`：

```bash
cd ~/yuhang_workspace/算法/DexGraspVLA-/SO101
PYTHONPATH= ~/miniforge3/envs/dexgraspvla/bin/python -m atom_robot.ar5.collect --show-config   # 只打印参数，不碰硬件
```

一条 episode = 一个 `.npz` + 每路相机一个 `.mp4`。

**OmniPicker 的数据是软件对齐过的**（10-21 起，`atom_robot/ar5/sync_align.py`）：采集时两路相机每一帧、臂每圈、夹爪每个读数都带时刻全量记下来，存盘前以**腕部 305 的每一帧为一行**对齐 —— 臂的关节角和夹爪开合按时间加权插值到这一帧的拍摄时刻，末端姿态用球面插值，夹爪指令取当时生效的值，顶部 335 取时刻最近的一张；暂停前后分段对齐、不跨暂停插值。所以行间隔就是相机自己的 33.3 ms，不再是回路节拍的 40/40/20 ms 轮换。数组名字和含义不变，转换脚本不用改。存盘时打一行「对齐」：行数、插值用的两点相隔多久、顶部图离基准多远。

| 数组 | 形状 | 内容 |
|---|---|---|
| `state` | (T, 8) | 7 个关节角（rad）+ 末端开合（0~1，0 合拢） |
| `action` | (T, 7) | 末端位姿**增量** 6 维 + 末端开合 1 维 |
| `ee_pose` | (T, 6) | 末端绝对位姿，位置 m + 轴角 rad |
| `held` | (T,) | 这一帧是不是在 P 保持中（见第 4 节） |
| `timestamp` / `fps_measured` | (T,) / 标量 | 每帧相对第一帧的秒数 / 实测帧率。**OmniPicker 暂停（不录帧）那段已扣掉**，时间戳是连续的；数据里**故意不留暂停记录**（用户 10-20：数据集里要看不出采集时的中断），停了几次只打在 collect.log |
| `t_cam_front` / `t_cam_high` | (T,) 各一个 | **OmniPicker（10-21 起，软件对齐）**：`t_cam_front` 就是 `timestamp`（腕部 305 的内核拍摄时刻）；`t_cam_high` 是这一行选中的那张顶部图的时刻（只有「程序收到」的时刻，比真正拍摄晚一个看不见的固定延迟，`collect.py` 的 `SYNC_LATENCY` 扣掉它比腕部晚的那一截再挑：10-21 用 `python -m atom_robot.ar5.diag_camera_latency` 开关灯 17 次量的是 7 ms，换相机 / 线 / 分辨率后重量）。和 `timestamp` 同一个零点、同样扣掉暂停 |
| `raw_arm_t` / `raw_arm_q` / `raw_arm_ee`、`raw_gripper_t` / `raw_gripper`、`raw_cmd_t` / `raw_cmd` | 各自长度 | **OmniPicker 的原始数据**：臂每圈（50 Hz）读的关节角和末端位姿、夹爪 100 Hz 的实测开合、每圈下发的夹爪指令，各带读取时刻（同一个零点、同样扣暂停）。对齐后的 `state` / `ee_pose` / `action` 就是从它们插值出来的，留着可以重算、查对齐 |
| `t_cam_high` / `t_cam_front` / `t_arm` / `t_gripper` | (T,) 各一个 | **其他末端（航凯、因时手）**：仍是 30 Hz 节拍上「最新一张图 + 当下的臂」，这几列记各来源的时刻：这张图的拍摄时刻、读关节角那次调用的中点、夹爪开合读数的读取时刻。和 `timestamp` 同一个零点、同样扣掉暂停，可以直接相减看同步；拿不到是 nan |

**动作空间是增量，不是绝对关节角。** 这和 servoJ 那条路不一样，两边的数据不能混在
同一个数据集里。但**转 DexGraspVLA 时两条路都能转** —— 关节角本来就在 `state` 里，见第 7.2 节。

```
1 环境 → 2 查主臂 → 2.5 末端（夹爪 / 手） → 3 查相机 → 4 采集 → 5 回放+自动检查 → 6 删和编号 → 7 转数据集
```

## 1. 环境

| 环境 | 干什么 | 关键依赖 |
|---|---|---|
| **`dexgraspvla`** | **主从臂遥操 + 采集**，`atom_agent.py` 也在这儿 | scservo_sdk、xCoreSDK、cv2、numpy |
| `lerobot` | 转 lerobot 数据集 | lerobot |

- 用 `dexgraspvla` 的原因：`atom_agent.py`（网页远程采集的工作站代理）默认 `--env-record dexgraspvla`，两边不一致的话代理一调就报 `No module named 'scservo_sdk'`。
- `scservo_sdk` 是**纯 Python、只依赖 pyserial**，是**直接把目录复制进去的，没走 pip** —— 这个环境的 torch 是配死的，
  pip 解依赖有可能动到它。要撤销就删掉 `~/miniforge3/envs/dexgraspvla/lib/python3.11/site-packages/scservo_sdk`。
- **`placo` 没装**（编译包，装进 3.11 有 numpy ABI 风险）。它只被笛卡尔那条遥操路（`teleop.py`）用到，
  所以自检里有 6 项报「跳过」而不是「失败」。自检命令和正常结果见 [工作区说明](../../../工作区说明.md) 第 5 节。
- 转数据集那步换 `lerobot` 环境，见第 7 节 —— 那个环境的 torch 也是配死的，两边不能混。

## 2. 查主臂

**怎么接**：两根线都要插 ——

1. 主臂舵机驱动板的 **USB** 插电脑。板上是 CH340 串口（`1a86:55d3`，序列号 5B79051033），
   by-id 是 `/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B79051033-if00`（10-20 核对过）。
2. 驱动板接**舵机电源**（主臂原配的适配器）。**USB 只给串口芯片供电，不给舵机供电**：
   只插 USB 时串口照样能开，但舵机一个都不回（`probe_leader` 报 `no reply`），看着像程序的问题。

```bash
P=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B79051033-if00
PYTHONPATH= ~/miniforge3/envs/dexgraspvla/bin/python -m atom_robot.ar5.probe_leader --port $P           # ping 舵机
PYTHONPATH= ~/miniforge3/envs/dexgraspvla/bin/python -m atom_robot.ar5.probe_leader --port $P --watch   # 实时看六个关节角
```

**给 `--port`，别让它自己扫。** 不给的话它会把所有 `ttyACM*` / `ttyUSB*` 都 ping 一遍，
包括 OmniPicker 的 USB-485（也是 ttyACM），等于往夹爪的总线上灌舵机协议。

SO-101 是 6 个 Feetech STS3215，ID 1~6，波特率 1000000。串口用 by-id（`CollectConfig.leader_port`）：
**`ttyACMn` 按插入顺序给**，10-20 实测夹爪的转换器先插，主臂就成了 `ttyACM1`，原来写死的 `/dev/ttyACM0` 会开到夹爪那边去。
用的是 `scservo_sdk`，不是 lerobot —— 装 lerobot 会动到这个环境配死的 torch。

**主臂全程不上力矩**，所以它一直可以徒手掰。程序每次启动都会查一遍，有哪个舵机在锁力矩就警告。

关节怎么映射到 AR5（`atom_robot/ar5/joint_mapping.py`）：

| 主臂关节 | AR5 | 符号 |
|---|---|---|
| shoulder_pan | j0 | −1 |
| shoulder_lift | j1 | +1 |
| elbow_flex | j3 | +1 |
| wrist_flex | j5 | +1 |
| wrist_roll | j6 | −1 |
| —— | j2、j4 锁死不跟 | |

**末端的输入是 6 号舵机**，也就是手柄扳机。标定端点 +55.5°（合拢）到 −55.5°（全开），
归一化成 0~1。读不到扳机时按 **1.0 也就是全开**处理，不是合拢。

### 标定文件的两个坑

标定存在 `atom_robot/ar5/joint_calibration.json`，由 `teleop_joint --save` 写。

* **`scale_overrides` 会盖过 `--relative`。** 存了缩放的那几个关节就不是 1:1 了，
  现在 `shoulder_pan` 1.0、`shoulder_lift` 0.617、`wrist_flex` 0.402。要看真实缩放
  就读启动时打印的 `scale` 那一列，别信注释。
* **`wrist_roll → j6` 的符号没验过。** 手腕转反了就
  `PYTHONPATH= ~/miniforge3/envs/dexgraspvla/bin/python -m atom_robot.ar5.teleop_joint --flip wrist_roll --save` 重存。

### OmniPicker

接线、夹爪里的设置、实测规矩、单独调试命令都在 **[omnipicker/README.md](omnipicker/README.md)**，这里只说采集相关的：

- **按数据集采，存到 `~/atom_episodes/new/任务名/`**，每个任务一个目录（给了 `--out` 就用它当根目录）。
  目录里除了每条的 npz + mp4，还有 `dataset.json`：任务名、语言 prompt、这个数据集用的夹持力和速度。
- **用另一套按键，主臂扳机全程不起作用，夹爪只听键盘：空格夹紧、O 松开**（2026-10-20 定的）。**每一步能按的键都会在那一步打出来**：

  | 步骤 | 终端显示 | 键 |
  |---|---|---|
  | 待机 | 按键说明，下面一行一个列出已有的数据集：名字、几条、语言 prompt（每次回到待机都列） | **P** 开一个数据集，q 退出 |
  | 1 任务名 | `任务名称是:` | 输入后**回车**；退格删字，Esc 取消。空格会换成 `_`，它就是目录名 |
  | （同名） | `已经有这个数据集「…」（已存盘 N 条；沿用…），是否要续采？` | `new/` 下有这个目录就问（**一条没存也算**）。**y** 续采：语言 prompt、力和速度都沿用 `dataset.json` 里的，**不再问、不再测**，夹爪自动张开一次后直接到待录；哪项没记下才补问那一步。其他键重新输名字 |
  | 2 语言prompt | `语言prompt是:` | 输入后**回车**（新数据集才有这一步） |
  | 3 测试力度和速度 | 当前力和速度；**进这一步时夹爪自动张开一次**（上电时它会自己合拢找零位） | **↑↓** 夹持力（32~128，每档 16，默认 64）、**← →** 速度（32、48 … 240、255，默认 128）、**空格** 夹紧、**O** 松开，试一下；测试完按**回车**。**整个数据集都用这一组力和速度**，记进 dataset.json，续采时沿用 |
  | 待录 | `开始采集数据集，按回车开始采集：` | **回车** 开始录这一条；空格 夹紧、O 松开（摆现场用）；**N** 删掉这个数据集编号最大的那条（先显示是哪条，**y 确认**才删，其他键取消；可以连着往前删）；**T** 回到测试那一步重新调力和速度（**只在这个数据集一条都没存时**，调好回车写回 dataset.json；续采会沿用记下的力和速度、跳过测试，用它补调，10-23 起）；**P** 换下一个数据集；q 退出 |
  | 录制 | `● 开始录「任务名」episode k` | **回车** 暂停（臂冻住、**停稳后不录帧**，**暂停时空格、O 都不起作用** —— 动了夹爪接着录时开合会跳一下），再按回车从主臂当前位置接着录；**空格** 夹紧、**O** 松开 —— **臂先冻住、只动夹爪，夹紧要等夹爪报「夹住」（夹持力建起来了；空夹就是合到底）、松开要等张开到位，最多等 4 秒，臂才自动接着跟**（2.5s 渐入），这段照常录帧，录下来就是「停下、夹、再走」；**S** 存盘、**R** 丢掉，臂都回 0 位，回到待录 |

- 采够 `-n` 条（默认 50）这个数据集就结束，回到待机，按 P 开下一个；不会退出程序。
- **N 可以连着往前删**（10-20 起）：每次删磁盘上这个数据集编号最大的那条，以前几次运行存的也删得到；
  每条都先显示要删哪条、按 **y** 才删（删了找不回来），q、回车等其他键都只是取消。
  删完下一条的编号接在剩下的最大编号后面；删的是这次运行存的，`-n` 的计数也跟着退。
- 输入文字时 q、s、空格都是字，要退出先按 Esc。输入期间臂照常保持、不会锁死。
- **不管新采还是续采，开数据集时夹爪都先自动张开一次**（进测试那一步，或者续采直接进待录时）。
  夹爪上电会自己合拢找零位，不张开的话第一下空格「夹紧」看不出变化。
- **空格只管夹紧、O 只管松开**（10-20 起）。原来空格是夹 / 松交替：夹在物体上时夹爪停在半合，
  看着像没夹紧，再按空格想夹 —— 实际是松开。现在已经夹着再按空格只提示「已经是夹紧了」，不动。
- **暂停后臂滑到停稳这一小段照录**（10-20 晚起）。暂停时臂的目标停在最后一条指令上，实测位置落后它一截，
  按下暂停后臂还会往前滑。原来一按就不录，这段滑行没录进去，接着录的第一帧臂已经在滑完的地方 ——
  black_sleeve 前 10 条每条有 2~8 处一帧跳 5~33 mm（平时每帧 1.5 mm），视频跳一下，action 也是离群的大增量。
  现在连续 2 帧关节每帧变化 < 0.005°、开合不变才停录，最多 2 秒（`omnipicker/keyflow.py` 的 `SettleWait`）。
- **录制中夹紧后要等「夹住」才放臂**（10-20 起）。原来是「位置 0.25 s 不变就算动完」，实测夹爪刚碰到套筒
  位置就不变了、力还没建起来（约 0.5 s 后才报夹住），臂这时就开始跟，套筒被带歪没夹牢。
  终端会打 `夹住了（停在开度 0.18）` / `夹爪到位` / `⚠ 等了 4s 夹爪还没夹牢 / 到位，不等了`。
- 存盘、丢弃之后夹爪停在原地，不自动松开。
- 状态行**只在变了的时候打一行**（阶段、数据集、已存条数、夹爪夹紧/松开/夹住、力、速度），
  例如 `▸ ● 录制  「black_sleeve」已存3条  夹爪夹住  力64  速128`；开度和录了几秒不放进去（一直在变会刷屏），
  录了多久存盘时打出来。预览窗右下角 `F64 V128`，暂停时是黄点。
- 数据里 `action` 的末端维记的是空格 / O 给的指令（0 夹紧 / 1 松开），`state` 末端维是夹爪实测开合。
- 开合 0~1 对应位置 0~210（最大张开约 99 mm），**不到 255**：从夹紧状态松开、目标又靠近张开端时会冲过头，
  冲过 255 就回绕、固件跟着乱，只能断电重启。10-20 采集时上限还是 240，速度 176 松开时回绕过一次，实测后降到 210。
- **这套键还没接到网页**，OmniPicker 加 `--remote` 会直接拒绝启动。
- 参数：`--omnipicker-force`（初始夹持力）、`--omnipicker-speed`（初始速度 32~255，默认 128）、`--omnipicker-port`。
  要持久改就改 `omnipicker/config.py`。**不用 `--gripper-*` 那组**，那是航凯的，单位不一样。
- 驱动发现位置回绕、卡死、错误码时**停发并退出采集**，按提示断电重启夹爪。

### 夹爪参数

**型号 HKVR-TG9801**（航凯微电），三维触觉、柔性抓取的两指电动夹爪。

| 项目 | 参数 |
|---|---|
| 行程 | 0~98 mm |
| 单指夹持力 | 0~20 N |
| **打开 / 闭合时间** | **0.5 s / 1.6 s** |
| 位置重复精度 | 0.2 mm |
| 触觉传感器 | 1 个，**三维** |

### 接线与通信

- **走 RS485**：电脑经 **USB-RS485** 接夹爪，黄 A、绿 B、黑 GND、红接独立 24 V。默认 **1 Mbps、8N1、Modbus 从站 1**。
  如果夹爪被设成手册里的「RS485 自定义协议」模式，先用厂家上位机设回 Modbus RTU；本程序不会盲写协议切换，也不写 EEPROM、不改设备 ID。
- **串口写 by-id，别写 `/dev/ttyUSB0`**：本机同时插着 CH340（手的 USB-CAN）和 Prolific（夹爪的 USB-RS485），
  `ttyUSBn` 按插入顺序给，重插一次就互换，接错的表现是完全没有回包。`--gripper-port` 的默认值就是 `HKVRConfig.port` 里那条 Prolific 的 by-id 路径，不用在命令行给。
- 不能把因时手的 USB-CAN 当 USB-RS485 用。
- 9-22 走若比特 USB-CAN 那条路一直没有回包（诊断见 [CAN诊断_2026-09-22](CAN诊断_2026-09-22.md)），**9-23 改走 RS485 就通了**，CAN 那条路已放弃。
  代码里还留着 `--gripper-transport can`。
- 力位模式的速度和目标位置必须用功能码 0x10 一次写两个寄存器。位置 0~1000（0 闭合，1000 全开），速度 200~1500，目标力寄存器 1~100（**不是牛顿**）。
- **目标力实际是 20**：`config.py` 的 `HKVRConfig.force` 是 50，但命令行 `--gripper-force` 默认 20，会把它盖掉。要 50 就显式加 `--gripper-force 50`。
- 驱动的串口 I/O 在独立线程里，只保留最新目标，不会因为夹爪等回包而拖住机械臂循环；异常回复、CRC 错误和断线不会当成控制成功。
  夹爪先连上才启动机械臂；运行时反馈失效会请求机械臂停止并退出，不自动重连。退出不会自动松夹。

### 夹爪什么时候跟扳机

**`collect` + OmniPicker：扳机不起作用，夹爪只听空格（夹紧）和 O（松开）**（2026-10-20 起，见上面 OmniPicker 一节）。

**航凯夹爪、因时手，以及 `teleop_joint`（不管什么末端）都还是一连上就跟扳机。** 离合只管臂、不管夹爪：
`mapper.gripper_command(joints)` 每帧无条件算、无条件下发，一连上夹爪就跑到扳机位置，指间有东西就会被夹住。
用它们之前先把主臂扳机推到张开那一端，或者确认夹爪指间是空的。

映射（标定 `closed=+55.5°`、`open=−55.5°`，驱动位置量程 0（开）~1000（闭），闭合端 9-24 从 858 改成了 1000）：

| 扳机角 | opening | 夹爪位置 | |
|---|---|---|---|
| +55.5° | 0.000 | 1000 | 闭 |
| 0° | 0.500 | 500 | 中间 |
| −55.5° | 1.000 | 0 | 开 |

**方向对不对不用猜**：起来之后先别按空格，来回扳主臂扳机，看终端状态行的 `手 X.XX`（预览窗右下角也有）。
松开扳机数字应该往 1 走、捏紧往 0 走。反了就把 `joint_calibration.json` 里 `gripper_closed_deg` 和
`gripper_open_deg` 对调。这一项**之前反过两次**，所以每次换主臂或重标定都要重看。

### 夹爪比回路慢得多

**闭合要 1.6 秒，张开 0.5 秒**，而录制是 30 Hz（33 ms 一帧）。夹爪指令写进数据的那一刻，实际夹爪还要再走最多 48 帧才到位：

* 数据里 `action` 的末端维**领先**实际开合最多 1.6 秒。学出来的策略也会有这个相位差，评测时别当成模型抖。
* 采数据时**合拢之后要停一下再抬臂**，不然抓取还没完成臂就走了。

`state` 最后一维是夹爪反馈，`action` 最后一维是扳机指令，两者不会同步到位。

### 接通之前采的数据

夹爪 9-23 接通之前采的数据，末端那一维记的是**操作员扳机的位置**，不是夹爪的实际开合。
臂那一侧是完整的，末端那一维只是意图。**和接通之后采的不要混成一个数据集。** 因时手的数据和夹爪的数据也要分开放。

### 负载

夹爪自重 **400 g**，推荐负载 1500 g。`config.py` 的 `payload_mass` 还是 0，
控制器会把这部分自重当成外力。要改先把末端加转接板整个称一遍，别照搬 400。

## 4. 采集

```bash
PYTHONPATH= ~/miniforge3/envs/dexgraspvla/bin/python -m atom_robot.ar5.collect \
    --preview \
    --out ~/atom_episodes/pick_bolt \
    --task "pick up the bolt and put it in the blue sleeve" \
    -n 20
```

* 末端默认是夹爪（`hkvr`）；用灵巧手加 `--end-effector inspire`。
* `--out` 默认 `~/atom_episodes`。**一个任务一个子目录**；Vision Pro 那条线默认也存到 `~/atom_episodes`，两条线别混在一个目录。
* `--preview` —— 想边采边看才要，见下。
* 相机默认两路全上；只想采一路加 `--cameras cam_high`（腕部的问题见第 3 节）。
* `--depth`（10-30 起，只在 `--end-effector omnipicker` 下）：两路相机的深度一起存，数据集目录里复制一份 `calib/` 标定。
  格式见 [数据集格式说明.md](数据集格式说明.md) 4.7。带深度的统一存到移动硬盘：
  `--out "/media/crp-5070ti-01/My Passport/top_error/with_depth"`。**别和没深度的数据集混在一个目录**。
  相机打不出深度会在开机时直接报错，不会悄悄不存。
* **开机默认先回 0 位**（`--no-home-on-start` 跳过）。
* 先只看参数、不碰硬件：把上面的命令加 `--show-config`。

### 边采边看画面（`--preview`）

开一个本地窗口，几路相机横着拼在一起，底下一条状态：在录还是待机、第几条、多少帧、末端开合、采了几条 / 目标几条。
刷新 15 Hz（`CollectConfig.preview_hz`），独立线程，主回路不碰 GUI，预览挂了不影响采集。

**别去点那个窗口。** 按键是从终端读的，焦点一跑到预览窗上，空格 / s / r / ← 全都不响应 ——
而且终端那边看着一切正常，只是你按什么都没反应。点回终端就好了。

远程那条路（`--remote`）是另一套，画面写 `live.jpg` 由代理转给网页，两者互不干扰。

### 键盘

| 键 | 做什么 |
|---|---|
| **空格** | 开始录这一条。**同时接合**，从臂开始跟主臂 |
| **P** | **保持 / 重新锚定**（**只在录制中有效**）。臂原地不动，主臂随便摆；再按一下从主臂新位置接着跟 |
| **s** | **这段做完了**：存盘 + 松开 + 臂回 0 位 |
| **r** | 丢掉正在录的这条，重来。编号不变。**臂也回 0 位** |
| **←** | **删掉刚存的那条**。只删最近一条，连按不会往回删 |
| **↑ ↓** | 调夹爪夹持力，一次一档（只有 `omnipicker` 支持，其他末端会提示不支持）。随时可按 |
| **q** | 退出。正在录的那条不保存，要留就先按 s。**臂先回 0 位再退** |

**录着就是接合、不录就是松开。** 这两件事同进同出：不录的时候从臂跟着主臂动，
只会让你摆现场时臂在旁边乱晃，以及下一条开录时臂不在起点。

**`r` 和 `←` 的区别**：`r` 丢的是还没存的、正在录的那条；`←` 删的是已经存到磁盘上的上一条。

**存完不会自动开下一条。** 臂自己回初始位置，你摆好现场再按空格，没有倒计时。

整个过程的控制台输出留一份在 `--out` 目录下的 `collect.log`，臂抱死之后要查的就是它。

### 0 位是哪个姿势

**s / r / q 三个出口臂都回 0 位**，这样每条的起点都一样。`←` 不回 —— 它只删磁盘上的文件。

回的是 `joint_calibration.json` 里的 **`centre_joints`**，也就是**主臂六个关节全零时从臂该在的姿势**：

```
centre_joints  [-30.2, 3.2, 7.0, 90.0, -93.2, 6.2, 0.7] 度
```

**不是 `config.arm.home_joints`**（`[0.4, 18.9, -1.0, 110.4, -47.7, 3.8, -8.2]`，Vision Pro 遥操回的是这个）——
两者差到 45.6°（j4）。回错的后果是每条都从偏 30~45° 的地方起步，主臂行程被不对称地吃掉一半。

要重标这个 0 位：把主臂摆到零位，`teleop_joint --save`。

**采集没开着、单独把臂送回 0 位**（卡住 / 抱死 / 掉电之后）：

```bash
PYTHONPATH= ~/miniforge3/envs/dexgraspvla/bin/python -m atom_robot.ar5.home_collect --check   # 只诊断，不动
PYTHONPATH= ~/miniforge3/envs/dexgraspvla/bin/python -m atom_robot.ar5.home_collect           # 诊断 → 上电 → 问一次再动
```

参考 VR 那边的 `home_arm.py` 写的：不开 RT、走控制器自己规划的 MoveAbsJ，不吃跳变门；
但回的是**采集的 0 位**（home_arm 回的是 VR 的 home_joints），有参数解析（`--help` 不会动臂），
默认不改控制器负载，到没到位以编码器为准。采集开着时它拒绝运行。
上电失败时：`ec=-3` 是急停按着，`ec=-513` 是示教器占着控制权（在示教器上切到自动）。

### P：主臂行程不够时用

臂要往一个方向走很远时，**主臂先到头了**。按 P 把臂停住、把主臂收回来、再按 P，
臂就从主臂的新位置接着往前 —— 跟抬鼠标一个道理。

```
空格 开录 → 往前推到主臂到头 → P（臂停住）→ 主臂收回来 → P（接着跟）→ … → s
```

* **臂原地不动**，**末端也冻住**在按 P 那一刻的开合（摆主臂时扳机难免蹭到）。
* **这几帧照常录，并在 npz 里逐帧标进 `held`**。它们 action 接近 0、画面静止，**不是坏数据**，训练时想丢就按 `held` 筛。占比超过一半才会在存盘时提醒一句。
* 再按 P 之后有 **2.5 秒渐入**（`ramp_seconds`，只能改 config），这段臂跟得比主臂慢。
* 不在录制中按 P 不起作用；`s` / `r` / `q` 都会清掉保持状态。

| `--no-home-on-start` | 关 | 开机不回 0 位 |
| `--preview` | 关 | 开本地窗口边采边看 |
| `--remote` | 关 | 网页驱动，被 `atom_agent.py` 拉起来时必须加 |
| `--show-config` | | 只打印参数，不碰硬件 |

`--reset-time` 和 `--warmup-time` 已经废弃，给了会被忽略并打印提示。

### 采的时候注意

* **每条都要换位置。** 物体摆在同一个点采 100 条，训出来的策略只会走那一条轨迹。
* **末端要真的开合。** 全程不动的话 action 第 7 维是常数，那一维学不到东西。这是最常见的废数据，存盘时会当场提醒。
* **一条别太长。** 30 秒够做一次抓放，太长的条目里大半是空转。
* **一批之内相机路数不能变。** 中途有一路掉了就停下来救（见第 3 节），别用一路接着采同一批。

### 臂动着动着就不跟主臂了，停在那儿

臂停下来一共**四种**原因，`collect` 每秒查一次，涨了就当场打一行并说出是哪个轴：

| 原因 | 现象 | 怎么救 |
|---|---|---|
| **latch** | 全停，程序退出并报错 | 回路堵了 >0.25s。退出时会问要不要救，按 y 才动臂 |
| **撞软限位** | **顶住的那个轴不动，别的还跟** —— 看着像"歪着不动" | 把主臂往回搬 |
| **跳变被拒** | **全停**，程序不报错 | **会雪崩**，见下 |
| **主臂丢包** | 对应关节这几帧不动 | 零星几帧无所谓；一直涨说明串口丢包 |

**跳变被拒为什么会雪崩**：一帧跳变超过 `joint_jump_max`（0.15 rad = 8.6°/帧）就被驱动拒掉，而**被拒之后参考点 `_q_cmd` 不前进**
—— 于是下一帧算出来还是同样大的跳变，一路拒到底。臂就一直停在那儿，直到你**把主臂慢慢搬回拒绝发生的位置**。

```
  ⚠ 臂没完全跟上：目标撞软限位 30 帧（轴1 顶住了）
  ⚠ 臂没完全跟上：跳变被拒 7 次 —— **这个会雪崩**，把主臂慢慢搬回刚才的位置就能恢复
```

这几行不影响采集，只是告诉你臂为什么不动。收工时还会汇总本次一共报了几次。

## 6. 删数据和编号

采集时按 `←` 就能删掉刚存的那条，npz 和 mp4 一起删，编号退回去让下一条重新占。

事后要删，**不要手动 `rm`**：一条是一个 npz 加每路一个 mp4，只删 npz 会留下孤儿 mp4，
后面的检查和转换就对不上。

- **编号有空洞不用管。** 续采时下一条的编号是**已有最大编号 + 1**，不是文件数，中间删掉一条不会撞车。
  空洞也不影响下游：`to_lerobot.py` 按文件名排序读，lerobot 自己重编 `episode_index`。
  **要重排就等整批采完、检查完、转完之后再排一次**，中途重排会让回放笔记、`head_bbox.json` 全部对不上。
- **文件名不用改。** `episode_%04d.npz` + `episode_%04d_<相机名>.mp4` 已经够用，任务描述、时间戳、实测帧率都在 npz 里。
  **一个任务一个 `--out`**，比在文件名里区分任务干净得多。

## 附：写盘为什么在后台线程

实测 600 帧 + 2 路相机同步存盘要 **2.21 秒**，而臂的 sender **0.25 秒**收不到目标就
刹车并 latch。在回路里同步存盘等于每存一条就有一次锁死机会。2026-09-03 就是这么
废掉三条数据的：第一条存的时候臂正好停着，侥幸活了；第二条存的时候臂还在动，
锁死，之后 600 帧 × 2 条全是一动不动的死数据。
