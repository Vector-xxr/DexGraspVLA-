# OmniPicker 抓取数据集：格式与接入说明

写给要把这批数据接进模型（训练或部署）的人。2026-10-29 整理。
所有字段都对照采集代码和真实数据核对过，文中数值以 black_sleeve 的 50 条为准。

---

## 速查

| 项 | 内容 |
|---|---|
| 机器人 | AR5 七轴臂 + OmniPicker 二指夹爪 |
| 遥操方式 | SO101 主臂，关节一对一映射；**j3、j5 锁死，实际只有 5 个关节在动** |
| 帧率 | 30 Hz，以腕部相机的帧为准，帧间隔 33.26~33.36 ms |
| 相机 | 俯视 `cam_high`（Gemini 335）、腕部 `cam_front`（Gemini 305），640×480，mp4 |
| `state` | 8 维 = 7 个关节角（弧度，实测）+ 夹爪开度（0 合 ~ 1 开，实测） |
| `action` | 7 维 = 末端位姿增量 6（**上一帧到这一帧**，实测）+ 夹爪指令 1（只有 0 和 1） |
| `ee_pose` | 6 维 = 法兰在基座系下的位置（米）+ 轴角（弧度） |
| 语言 | 每个数据集一句英文提示语 |
| 深度、相机内外参 | 第 1 节这四个数据集**没有**；10-30 起加 `--depth` 采的（`top_error/with_depth/`）有，见 4.7 |

## 2. 目录结构

```text
<任务名>/
├── dataset.json                  任务名、提示语、夹持力、夹爪速度
├── episode_0000.npz              数值数据（见第 4 节）
├── episode_0000_cam_high.mp4     俯视相机
├── episode_0000_cam_front.mp4    腕部相机
├── episode_0001.npz
└── ...
```

* 一条数据 = 一个 npz + 两个 mp4，文件名前缀相同。**按文件名排序读，不要假设编号连续。**
* 转过 DexGraspVLA 的数据集目录里还会多出 `head_bbox.json`、`h100/` 等，和本文无关，见 [数据转换说明.md](数据转换说明.md)。

`dataset.json` 示例：

```json
{
 "created": "2026-10-20 13:53:31",
 "task_name": "black_sleeve",
 "prompt": "pick up the black sleeve",
 "updated": "2026-10-22 10:38:23",
 "grip_force": 64,
 "speed": 176
}
```

`grip_force`、`speed` 是夹爪的寄存器值，不是牛顿或毫米每秒。同一个数据集里所有条都用这一组。

## 3. 约定

| 项 | 约定 |
|---|---|
| 坐标系 | AR5 基座坐标系，z 朝上 |
| 位姿参考点 | **法兰**（臂末端安装面），**不是夹爪指尖**，夹爪长度没算进去 |
| 姿态表示 | 轴角（旋转向量）：方向是转轴，模是转角。由控制器给的欧拉角换算而来，`R = Rz(rz)·Ry(ry)·Rx(rx)` |
| 关节顺序 | j1 ~ j7，对应控制器的轴 1 ~ 7 |
| 夹爪开度 | 0 = 全合（位置 0），1 = 位置 210，约 99 mm。换算：开度 = 位置 ÷ 210 |
| 时间 | 秒，每条第一帧为 0 |

## 4. npz 字段

### 4.1 `state`（T×8，float32）：实测状态

| 维 | 含义 | 单位 |
|---|---|---|
| 0–6 | j1 ~ j7 关节角，实测 | 弧度 |
| 7 | 夹爪开度，实测 | 0 ~ 1 |

* **j3（第 2 维）和 j5（第 4 维）全程是常数**：遥操时锁在 j3 = +7.0°（0.1218）、j5 = −93.2°（−1.6268）。
  这两维标准差为 0，按均值方差归一化时要防止除以 0。
* 夹爪夹住物体时开度停在物体宽度上，例如 black_sleeve 是 0.386 左右；换物体，这个值就不同。

AR5 软限位（弧度）：

| | j1 | j2 | j3 | j4 | j5 | j6 | j7 |
|---|---|---|---|---|---|---|---|
| 下限 | −3.1067 | −2.0944 | −3.1067 | −1.0472 | −3.1067 | −0.8727 | −0.8727 |
| 上限 | 3.1067 | 2.0944 | 3.1067 | 2.5307 | 3.1067 | 0.8727 | 0.8727 |

### 4.2 `action`（T×7，float32）：最容易用错

| 维 | 含义 | 单位 / 取值 |
|---|---|---|
| 0–2 | 末端平移增量 `p[t] − p[t−1]` | 米，基座系 |
| 3–5 | 末端旋转增量 `R[t] · R[t−1]ᵀ` 的轴角（在基座系下左乘） | 弧度 |
| 6 | 夹爪**指令** | 1 = 张开，0 = 夹紧，没有中间值 |

> **用之前必须知道的四点**
>
> 1. **这是「从上一帧走到这一帧」的增量，不是「从这一帧往下一帧走」。**
>    `action[0]` 的前 6 维恒为 0。要当作「第 t 帧该执行的动作」，得取 `action[t+1]`，见第 7 节。
> 2. **前 6 维是用实测末端位姿算出来的，不是下发给臂的指令。** 主臂下发的关节角指令没有存。
> 3. **参考点是法兰，不是夹爪指尖。** 绕法兰转一个角度，指尖会跟着平移。
> 4. **第 6 维是按键指令，不是开度。** 实测开度在 `state[:, 7]`。

前 6 维和 `ee_pose` 的关系可以直接验证：`action[t, :6] == pose_delta(ee_pose[t-1], ee_pose[t])`，实测误差不超过 2.4e-7。
`pose_delta` 和它的逆运算 `compose_pose` 在 [transforms.py](atom_robot/ar5/transforms.py)。
不用这个文件的话，用 scipy 写法如下：

```python
from scipy.spatial.transform import Rotation as R
# 增量：上一帧 a → 这一帧 b
d_pos = b[:3] - a[:3]
d_rot = (R.from_rotvec(b[3:]) * R.from_rotvec(a[3:]).inv()).as_rotvec()
# 叠回去：a + 增量 → b
b_pos = a[:3] + d_pos
b_rot = (R.from_rotvec(d_rot) * R.from_rotvec(a[3:])).as_rotvec()
```

### 4.3 `ee_pose`（T×6，float32）：末端绝对位姿

`[x, y, z, 轴角三个分量]`，是法兰在基座系下的位姿，单位米和弧度。

* 轴角的模最大到 2.93，已经接近 π。black_sleeve 里没有出现符号翻转（相邻帧每个分量最大只变 0.03），
  但如果模型直接用绝对姿态，**建议换成四元数（注意保持符号连续）或 6D 旋转表示**，以防别的数据集翻转。
* black_sleeve 的范围：x 0.18~0.45、y −0.41~−0.12、z 0.20~0.60（米）。

### 4.4 图像

| | `cam_high` | `cam_front` |
|---|---|---|
| 相机 | Gemini 335 | Gemini 305 |
| 安装位置 | 台架上，俯视 | 臂的腕部 |
| 分辨率 / 帧率 | 640×480，30 | 640×480，30 |
| 编码 | mp4v（有损） | mp4v（有损） |

* 用 `cv2.VideoCapture` 读出来是 **BGR**；用 PyAV、torchvision 等读出来是 RGB。
* **视频帧数和 npz 的 T 完全相等**（black_sleeve 50 条 × 2 路全部对上），第 i 帧图像对应 npz 第 i 行。
* 第 1 节的四个数据集两台相机都没存深度，也没存内参和外参。带深度的见 4.7。

### 4.5 时间与对齐

* **基准是腕部相机每一帧的拍摄时刻**：`timestamp == t_cam_front`。
* 臂的关节角、夹爪开度按这一刻做时间插值，末端姿态做球面插值。夹爪指令取这一刻正在生效的值，不插值。
* 俯视图取拍摄时刻最近的一张（已扣除 7 ms 固定延迟），离基准中位 8 ms、最大 19 ms。
* 采集时的暂停已经从时间轴上抹掉：时间戳连续，暂停前后的帧直接接上，暂停期间没有录帧。

### 4.6 其他字段

| 字段 | 形状 | 含义 |
|---|---|---|
| `task` | 标量字符串 | 提示语，和 `dataset.json` 的 `prompt` 相同 |
| `fps` | 标量 | 30.0（标称） |
| `fps_measured` | 标量 | 实测，约 30.02 |
| `timestamp` | (T,) | 每行的时刻（秒） |
| `t_cam_front` / `t_cam_high` | (T,) | 这一行用的两张图各自的拍摄时刻 |
| `camera_keys` | (2,) | `['cam_high', 'cam_front']` |
| `held` | (T,) | OmniPicker 模式下全是 False，可以忽略 |
| `raw_arm_t` / `raw_arm_q` / `raw_arm_ee` | (M,) / (M,7) / (M,6) | 未对齐的臂原始读数，约 49 Hz |
| `raw_gripper_t` / `raw_gripper` | (K,) | 未对齐的夹爪开度原始读数，约 99 Hz |
| `raw_cmd_t` / `raw_cmd` | (M,) | 未对齐的夹爪指令，随臂的读数频率 |

`raw_*` 一般用不到，想按别的频率重新采样时再用，时刻和 `timestamp` 同一个零点。

### 4.7 深度（10-30 起，`collect.py --depth`）

带深度的数据集在 `My Passport/top_error/with_depth/<任务名>/`，比上面多三样：

```text
<任务名>/
├── calib/                          开新数据集时复制的标定：top_extrinsic.json、wrist_handeye.json、depth_params.json
├── episode_0000_depth.zarr.zip     这一条两路相机的深度
└── episode_0000.npz                多两个字段 t_cam_high_depth、t_cam_front_depth
```

| | `cam_high`（335） | `cam_front`（305） |
|---|---|---|
| 数组 | (T, 480, 640) uint16 | (T, 480, 640) uint16 |
| 单位（`mm_per_unit`） | 1 mm | 0.1 mm |
| 对齐到彩色（`aligned_to_color`） | 是，像素和 `cam_high.mp4` 一一对应 | **否**，深度传感器自己的视角（视野比彩色大），要用 `calib/depth_params.json` 对齐 |
| 和彩色的关系 | 与同一行彩色是同一次读取的同一帧（`t_cam_high_depth == t_cam_high`） | 按拍摄时刻挑最近一张，10-30 实测比腕部彩色晚 2.8 ms、不抖 |

* 第 i 行深度对应 npz 第 i 行、两路视频第 i 帧。值为 0 = 没测到。
* 每块一帧，Blosc zstd 压缩；600 帧一条约 225 MB。
* 换算到基座系用 `atom_robot/ar5/camera_3d.py`：`load_rig(数据集/calib)`，腕部要传这一行的关节角。


## 5. 数据里的行为特点（影响建模）

| 现象 | 具体情况（black_sleeve） |
|---|---|
| 起始姿态完全相同 | 每条第一帧都是采集 0 位，标准差 0：`q0 = [-0.5272, 0.0554, 0.1218, 1.5711, -1.6268, 0.1083, 0.0125]`，夹爪张开 |
| 夹爪只动一次 | 50 条每条夹爪指令都只切换一次（1 → 0），发生在全条的 47%~93% 处（中位 83%） |
| 夹紧时臂停住 | 按下夹紧后臂冻住、等夹牢再接着动：静止 0~56 帧，中位 30 帧（约 1 秒）。这段静止是演示的一部分 |
| 指令到开度有滞后 | 以第 0 条为例：指令在第 306 帧变 0，开度第 309 帧开始下降，第 324 帧停在 0.386（约 0.6 秒） |
| 结尾 | 夹着物体抬起就结束，**没有放下、没有再张开**。模型学不到松手 |
| 只有 5 个关节在动 | j3、j5 全程不变，末端的 6 维增量其实只有 5 个自由度 |
| 每条长度 | 213~549 帧（7.1~18.3 秒），中位 333 帧 |

## 7. 怎么构造训练目标

第 t 帧的观测（图像 + `state[t]`）对应的动作，应该是「从第 t 帧走到第 t+1 帧」。

```python
import numpy as np

ep = np.load("episode_0000.npz")
state, action, ee = ep["state"], ep["action"], ep["ee_pose"]

# 方案一（推荐）：绝对关节角，第 t 行 = 第 t+1 帧的实测关节角，最后一帧重复自己
target_q = np.concatenate([state[1:, :7], state[-1:, :7]])

# 方案二：末端增量，第 t 行 = 第 t 帧到第 t+1 帧的增量，最后一帧补 0
target_dee = np.concatenate([action[1:, :6], np.zeros((1, 6), np.float32)])

# 夹爪：取下一帧正在生效的指令（0/1），最后一帧重复
target_grip = np.concatenate([action[1:, 6], action[-1:, 6]])
```

* 方案一和执行接口直接对得上（臂吃关节角），也是 DexGraspVLA 版本的做法。
* 方案二要在部署时自己解逆解，见第 8 节。
* 无论哪种方案，都要先处理 j3、j5 这两个常数维，可以直接去掉，或者在归一化时防止除以 0。

## 8. 部署时要和数据对上的

| 项 | 要求 |
|---|---|
| 起始姿态 | 先回采集 0 位 `q0`（第 5 节），命令见下方 |
| 执行接口 | `AR5Env.step_joints(7个关节角, 夹爪)`（[ar5_env.py](atom_robot/ar5/ar5_env.py)），关节伺服 |
| 频率 | 采集时回路以 50 Hz 给臂发关节目标、以 30 Hz 录帧。模型按 30 Hz 出动作，怎么补到 50 Hz（插值还是降频）**还没定** |
| 跳变保护 | 相邻两次下发的关节目标，任何一轴相差超过 0.15 rad 就整条拒收（`joint_jump_max`） |
| 高度保护 | 关节指令会检查臂最低点 z ≥ 0.10 m（`joint_floor_z`，这个值是按以前的因时手算的，换夹爪后没重算） |
| 夹爪 | 发 **0 或 1**：0 = 按设定夹持力自适应夹紧，碰到物体就停住夹着；1 = 张开到 210 |
| 夹持力、速度 | 设成该数据集 `dataset.json` 里的值（atom_robot 的 `--omnipicker-force`、`--omnipicker-speed`） |

回采集 0 位（走控制器自己规划的关节运动，不受跳变保护影响）：

```bash
cd ~/yuhang_workspace/算法/DexGraspVLA-/SO101
PY=~/miniforge3/envs/dexgraspvla/bin/python
PYTHONPATH= $PY -m atom_robot.ar5.home_collect --check   # 只诊断、打出目标姿态，不上电、不动
PYTHONPATH= $PY -m atom_robot.ar5.home_collect           # 诊断 → 上电 → 问一次再动
```

**不要把实测开度当夹爪指令发。** 比如套筒夹住时开度是 0.386，发 0.386 过去，夹爪走到这个位置会判「已到达」并卸力，物体就只是被松松含着。
只有 0 / 1 这种指令和采集时的行为一致。

**如果模型输出末端增量**：

* 要先用 `compose_pose(当前法兰位姿, 增量)` 得到目标位姿，再解逆解得到关节角；
* 数据里 j3、j5 是锁死的，逆解如果动了这两轴，关节状态就会跑出训练分布；
* 只有 5 个关节在动，模型给出的 6 维增量不一定都能走到；
* 参考点是法兰，不是指尖。

## 9. DexGraspVLA 用的版本

water_bottle、banana、black_box 已经各自转成了 DexGraspVLA 的 zarr（在各数据集目录的 `h100/` 下），和本文的原始格式有三处不同：

* 维度 8 = 7 关节 + 1 夹爪，关节按软限位归一化到 [−1, 1]；
* `action = 下一帧的 state`，也就是第 7 节的方案一；
* 夹爪用的是**连续的实测开度**，不是 0/1 指令。所以部署时这一维要往合拢方向减一点余量，否则会卸力。
  做法见 `算法/DexGraspVLA-/README.md`「部署：夹爪那一维要换算」。

转换细节见 [数据转换说明.md](数据转换说明.md)。

## 10. 读取示例

```python
import json
import cv2
import numpy as np

root = "/media/crp-5070ti-01/My Passport/top_error/black_sleeve"
meta = json.load(open(f"{root}/dataset.json"))
ep = np.load(f"{root}/episode_0000.npz")
T = len(ep["state"])

frames = {}
for cam in ("cam_high", "cam_front"):
    cap = cv2.VideoCapture(f"{root}/episode_0000_{cam}.mp4")
    imgs = []
    while True:
        ok, img = cap.read()          # BGR
        if not ok:
            break
        imgs.append(img)
    cap.release()
    frames[cam] = np.stack(imgs)      # (T, 480, 640, 3)
    assert len(imgs) == T

print(meta["prompt"], T, ep["state"].shape, ep["action"].shape)
```
